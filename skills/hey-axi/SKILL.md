# hey-axi: HEY email for agents

`hey-axi` runs Basecamp's HEY CLI (`hey`) and prints compact TOON. Lists show at most four columns and a count, long text is cut (the total size is shown), and suggestions name `hey-axi` commands. Every `hey` command works: `npx -y hey-axi <same args as hey>`.

Examples below use `npx -y hey-axi`, which works without installing anything. If `hey-axi` is installed globally (`npm i -g hey-axi`), drop the `npx -y`.

## 1. Start here

Run `npx -y hey-axi` with no arguments. It shows the mail for this directory's scope (the Imbox unless a `.hey-axi.json` says otherwise), a `count`, what the last session here did, and what to do next. If HEY is missing or signed out, it prints a `status` line and the fix instead.

Problems:
- `status: HEY CLI not found` (`kind: hey_missing`): install `hey`, or set `HEY_BIN=/path/to/hey` (cron/launchd jobs usually need `HEY_BIN=$HOME/.local/bin/hey`).
- `status: not signed in` (`kind: auth`): ask the **user** to run `npx -y hey-axi auth login --interactive` in their own terminal. It opens a browser, so without `--interactive` it is refused (exit 2); `tui`, `mcp` and the `setup` wizard work the same way. Never pass `--interactive` yourself. Don't try to sign in for them, and never print tokens (`auth token` is blocked unless `--allow-secret` is passed).
- `npx -y hey-axi doctor` finds other login and config problems. `npx -y hey-axi version` shows both versions.

## 2. Read and triage

```bash
npx -y hey-axi box list                          # boxes and their ids
npx -y hey-axi box view imbox --limit 25         # rows in a box (imbox, feed, papertrail, aside, later, …)
npx -y hey-axi thread read <topic_id>            # the thread (long bodies cut; --full for all)
npx -y hey-axi search "invoice" --from a@b.com --date last_30_days
npx -y hey-axi screener list                     # senders waiting to be screened
npx -y hey-axi set-aside view   |   npx -y hey-axi bubble list   |   npx -y hey-axi draft list
```

**Which id to use.** Each `box view` row has an `id` (the box item) and a `topic_id` (the thread):
- `topic_id` goes to `thread read`, `reply` and `forward`.
- `id` goes to `seen`, `unseen`, `move`, `label`, `bubble`, `trash`, `spam` and `ignore`.
- A row with kind `bundle` has no `topic_id`. Open it with `npx -y hey-axi bundle view <id>`.
- Screener commands take the clearance `id` from `screener list`. These aren't contact ids.

```bash
npx -y hey-axi seen <id>...           npx -y hey-axi unseen <id>...
npx -y hey-axi move <id>... --to feed          # imbox | feed | aside | later | papertrail
npx -y hey-axi label add <id>... --to "Receipts"
npx -y hey-axi bubble up <id>... --tomorrow    # exactly one of --now | --on <date> | --tomorrow | --weekend | --next-week
npx -y hey-axi screener approve <clearance-id>
npx -y hey-axi trash <id>...          npx -y hey-axi spam <id>...      npx -y hey-axi ignore <id>...
```

`trash`, `spam`, `ignore`, `screener deny --spam` and `screener clear` (which clears the whole queue) run without any confirmation. Confirm with the user before you run them in bulk.

Mutations are idempotent: when the desired state already holds (already seen, already deleted), the answer is `noop: true` with exit 0, not an error.

Output includes HEY's breadcrumb hints as `help` lines (with your `--account` carried over), plus `Run … --all for all N` when a list was cut. Follow them instead of guessing.

## 3. Writing mail: drafts by default

- `compose` and `reply` are **saved as drafts** automatically. The output starts with `sent: false`, `saved_as: draft` and an `axi_notice`. Tell the user that a draft is waiting in HEY. Don't claim it was sent.
  ```bash
  npx -y hey-axi reply <topic_id> --message "Thanks, Thursday works."
  npx -y hey-axi compose --to a@b.com --subject "Hi" --message "…"
  cat reply.md | npx -y hey-axi reply <topic_id> --message -
  npx -y hey-axi draft list   |   npx -y hey-axi draft show <draft-id>
  ```
- The message is required (`--message`, `--message-html`, `--attach`, or `--message -` to read stdin): HEY never opens an editor under hey-axi. The same goes for `journal write --content`, `contact note set --note` and `draft edit` (pass the fields to change).
- `forward`, `draft send` and `bulk-reply send` are **refused** (exit 2) because HEY has no draft mode for them. The error names the safe alternative.
- To actually send, the user must explicitly ask you to, and you add `--allow-send` (or they set `HEY_AXI_ALLOW_SEND=1`). Don't add it on your own initiative.

## 4. Output: fields, truncation, counts, modes

- **Lists show at most four columns** (for example `box view`: `id, topic_id, from, subject`). Pick others with `--fields id,subject,seen,at,creator.email_address`; aliases and dotted paths both work. `--fields all` keeps every field. An unknown field fails with exit 2 and lists the ones available. `npx -y hey-axi <command> --help` shows the defaults.
- **Long text is cut** at 1000 characters in detail views (thread bodies, drafts) and 120 in list cells, marked `… (truncated, N chars total)`. The output then includes a `Run … --full` help line. Use `--full` only when you need the whole text.
- **Every list has a `count`**: `N of T total`, `N total` (HEY said the list is complete), `N shown; more available` (then a help line says how to get the rest), or `N shown; no more pages reported` (HEY gave no total and no further page). Empty lists say `empty: 0 results for …`.

| Want | Use |
|---|---|
| Default: summary, count, data, help lines, as TOON | (nothing) |
| The same as compact JSON | `--json` |
| Less: data, count, empty state and hints only | `--quiet` |
| HEY's complete, untouched result | `--full` (combine with `--json` for raw JSON) |
| Raw HEY output | `--ids-only`, `--count`, `--markdown`, `--html`, `--styled`, `--jq '<expr>'` |
| Help for one command: usage, arguments, flags with defaults, examples, notes (no network) | `npx -y hey-axi <command> --help` |

Everything is checked before HEY runs (exit 2, with the fix inline): unknown commands (with "did you mean"), unknown flags (the valid ones are listed), flags without a value, values of the wrong type (`--limit abc`), missing or extra arguments (quote multi-word text), missing required flags such as `move --to`. Global flags like `--account <id|all>` can go anywhere.

## 5. Watching for changes

`npx -y hey-axi watch` streams each event as it arrives (a TOON block per event, separated by blank lines; add `--json` for HEY's NDJSON, one line per event) until it's interrupted. Use bounded forms in agent sessions:

```bash
npx -y hey-axi watch --box imbox --events new --exit-on-first --timeout 10m
```

Lines also include `ready`, `disconnected` and `resync`. On `resync`, re-read that box.

## 6. Errors and exit codes

Errors are TOON on stdout: `ok: false`, `error`, `kind` (`usage`, `not_found`, `auth`, `forbidden`, `rate_limited`, `network`, `api_error`, `ambiguous`, `hey_missing`, `command_error`), HEY's `code`/`hint`/`meta` when it gave them, and a `help` line with the next step. Exit codes: **0** success (including no-ops) · **1** error · **2** usage error or refusal (unknown command/flag/field, bad argument, blocked send, needs the user). Read `hint`/`help` before you retry.

## Install

```bash
# HEY CLI (macOS/Linux)
curl -fsSL https://hey.com/install-cli | bash        # or: brew install --cask basecamp/tap/hey
npx -y hey-axi auth login --interactive            # the user runs this once, in their own terminal

# hey-axi (optional: every example here also works as npx -y hey-axi …)
npm i -g hey-axi                                    # puts `hey-axi` on PATH
```

Session hook (the alternative to this skill; you only need one): `npx -y hey-axi setup hooks` (user-invoked) shows the home view at the start of every Claude Code, Codex and OpenCode session and records what each session did for the next one. `--project` limits it to one directory, and `--remove` undoes it. `npx -y hey-axi setup scope --label <name>` focuses a directory's home view on one label, box or search.
